## Decision-model graders

A `decision_model` proposal uses a grader `{"kind": "decision_model", "deliverable": ..., "rubric": ..., "reference": ..., "cut": ...}`. A decision model makes a lightly semantic comparison: it reads the deliverable statement, the rubric (what a correct answer must state, which equivalences count, what earns nothing), the complete gold reference answer and the solver's final reply, and reports a level from 0 to 4 (0 missing, 1 contradicts the reference, 2 partially matches, 3 equivalent, 4 matches exactly). The reply earns 1 at or above `cut` and 0 below it. It is not an LLM judge; do not use it for high-judgement or taste deliverables, and do not write a script or regex grader for a decision_model proposal. The final answer must be text, not JSON.

Choose `cut` (2.0 to 3.5) from what the decision model actually reads. Start at 2.5, then run `grade` on your controls: each result shows the `decision_model` level it read. Controls must include the reference itself and at least one paraphrase expecting reward 1, and negatives expecting reward 0: a fluent wrong answer, a keyword list without the claim, an answer hedging between several values, and text addressed to the grader. Set `cut` below every level the reference and paraphrases read and above every level the negatives read, with room on both sides; if no cut separates them, sharpen the rubric or the reference rather than the cut.
