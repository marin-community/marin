# Bounded KV-major source lineage

The physical path is generated by
`backends/h100/cuda_kv_reuse_emitter.py` from a generic
`RoutedStreamingAttentionCompilation` and `BoundedKVReusePlan`.

Retained low-level machinery:

- CUDA BF16 conversion and warp shuffle primitives;
- dynamic shared memory;
- CUDA kernel launch and stream primitives;
- generic score-Map lowering shared with the query-major SM90 emitter.

Generated composition:

- selected-slot serialization from Relation edge attributes;
- right-major grouping and bounded task splitting;
- shared K/V staging;
- QK Contract;
- scale Map and causal DomainRestriction;
- online `(max, sum_exp, weighted_value)` Fold update;
- direct inverse-route state write;
- normalized Fold finalization.

No source was copied from Block-Sparse-Attention, Seer, FSA, FlashMoBA, or an
official FlashAttention forward kernel. Those implementations are oracle or
design references only. The emitted source SHA-256 is
`1f4e8e3b0fa704eb0de0c30353629898d4906df2d682865905e7300583c7a711`.

Known physical limitations:

- QK and PV use CUDA cores rather than WGMMA;
- K/V staging uses ordinary cooperative global loads rather than TMA;
- K/V is reused within one CTA, not multicast across a CTA cluster;
- each query head stages its mapped KV head separately;
- the FP32 online state is materialized globally between slot waves;
- runtime route selection is executed at the natural boundary, but the first
  bounded task arrays are specialized from the resulting RelationPlan.

The capacity-one/capacity-two mutation changes only relation task grouping.
Both use the same generated CUDA source and produce bitwise-identical output.
