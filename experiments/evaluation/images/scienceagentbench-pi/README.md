# ScienceAgentBench Pi actor

The shared linux/amd64 image contains Pi 0.87.0, Node 22, and the pinned Python scientific stack. The EvalDash task uses the Dockerfile and `requirements.lock` as its build context. Daytona identifies the private snapshot by those files and the requested resources. A fresh actor and clean replay can reuse that snapshot across tasks and knowledge conditions.

The runner selects the files for the task’s released dataset directory and verifies each SHA-256 before upload. The image exposes `/setup_files/datasets` at `/testbed/benchmark/datasets`. Sandbox setup checks the files at those working paths before Pi starts or the submitted program runs. Evaluators, reference results, and judge credentials belong in the grading stage.

To regenerate the lock, copy `requirements.in` and `pilot.constraints` into an empty directory and run `uv --no-config pip compile requirements.in -c pilot.constraints --python-version 3.10 --python-platform x86_64-manylinux_2_28 --generate-hashes --no-header --index-url https://pypi.org/simple --output-file requirements.lock` there. The constraints preserve the earlier shared scientific stack. BioPsyKit depends transitively on docopt 0.6.2, whose published distribution is source-only. The Dockerfile permits hash-locked source builds for docopt, airr and docrep. All other scientific packages use wheels. PyTorch uses the pinned Linux CPU wheel. The Debian runtime library for rasterio is pinned by SHA-256 in the Dockerfile. Cartopy tasks receive the public Natural Earth map files during staging. The glacier tasks also stage the Salem world-border shapefile and OGGM regional metadata listed in `glacier-support.json`. Their OGGM configuration disables downloads. The RDKit drawing backend requires the X rendering libraries from the dated Debian repository snapshot in the Dockerfile. An expanded dependency set requires reference runs and a recorded snapshot identity before use in a cohort panel.
