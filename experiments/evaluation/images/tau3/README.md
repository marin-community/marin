# Tau3 Pi and ACP image

Tau3 uses the public `ghcr.io/marin-community/rollout-images` package for its main
sandbox and retail and airline user/judge runtimes. The main recipe adds the Pi
and ACP dependencies to the canonical Tau3 image. It preserves
`tau2-bench[knowledge]` at commit `fc0055dc4e0a316c3f83133267fbd6faaa770992`
and its data. The runtime images retain their canonical digests, including the
existing server and task configuration.

[`build.py`](build.py) declares the parent digest, Node archive and checksum,
platform and runtime digests as constants.
[`package-lock.json`](package-lock.json) locks Pi, pi-acp, acpx, the Pi MCP extension and their npm
dependencies. [`requirements.lock`](requirements.lock) locks the Python dependencies
with hashes. Both `python3` and `/opt/harbor-acp-venv/bin/python` install that same
lock and provide MCP and the ACP SDK. The image exposes `node`, `pi`, `pi-acp` and
`acpx` on `PATH`.
Harbor registers the installed MCP extension and the task's MCP servers in Pi's
runtime profile; the image supplies the packages without a user profile.
The extension is pinned to `pi-mcp-extension@1.10.0`; its SDK peers use
`@earendil-works/pi-ai@0.80.5` and `typebox@1.1.38`, matching Pi's own versions.

## Build or reuse

Authenticate Docker to GHCR with a token that can write packages. In the GHCR
package settings, set `rollout-images` visibility to **Public** before an Iris
worker uses it. The Dockerfile's repository source label links the package to the
repository; it does not change visibility. Stage the
canonical main, retail and airline manifests in `rollout-images`, preserving
their digests, before building the main recipe.

Preview the tag without contacting the registry:

```bash
uv run --no-project python -m experiments.evaluation.images.tau3.build --plan
```

Resolve or build the main image:

```bash
uv run python -m experiments.evaluation.images.tau3.build
```

The command hashes the Dockerfile, npm manifest, dependency locks and declared configuration into
`rollout-images:tau3-pi-<identity[:16]>`. An existing tag is reused. A missing tag
is built for `linux/amd64`, pushed with gzip layers, and read back from GHCR.
Authentication and other registry errors stop the command. It prints the
immutable image reference. Python callers use `tau3_image()` from the same module;
neither path requires a separate image-reference file.

Prepare a reviewed Tau3 task for Shellbox:

```bash
uv run python -m experiments.evaluation.images.tau3.build --task prepared-tasks/tau3-airline-0
```

This writes `environment/shellbox-images.json` with the main image and a runtime
built from the pinned domain image plus the task's own `server.py` and
`task_config.json`. Docker caches unchanged layers. Build metadata supplies the
pushed digest directly, so concurrent builds cannot select another task's tag.
The helper leaves the task definition and verifier unchanged. Set
`allow_internet = false` in the prepared task and remove unsupported storage
allocations explicitly before local admission.

`--repository` changes the main image's destination. `--base-image` accepts a
digest-pinned parent override and changes the dependency identity. The canonical
runtime references stay as declared in the manifest.

## Update dependencies

The pinned npm packages run inside the Tau3 evaluation sandbox. Their security
warnings are accepted risk for this use: Dependabot update PRs are ignored for
this directory in [`.github/dependabot.yml`](../../../../.github/dependabot.yml),
and alerts for `experiments/evaluation/images/tau3/package-lock.json` are dismissed
as **tolerable risk** in GitHub. The configuration does not suppress alerts for
new advisories; dismiss those separately under the same policy. Revisit this
exception if these dependencies are used outside the evaluation sandbox.

Edit `package.json`, `requirements.in` or the constants in `build.py`, then regenerate the
affected locks:

```bash
cd experiments/evaluation/images/tau3
npm install --package-lock-only --ignore-scripts --no-audit --no-fund
uv pip compile --generate-hashes --no-header --python-version 3.12 \
  --python-platform x86_64-unknown-linux-gnu requirements.in --output-file requirements.lock
```

Dockerfile changes automatically select a new image identity.
Multiple hashes on a Python requirement allow distinct wheels and source archives
for the same pinned release. They are generated by uv and retained for
`pip --require-hashes`; they are not repeated copies of one hash.
