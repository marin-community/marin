Grading patterns (from the held-out study of this campaign's earlier tasks): most accepted code graders let wrong answers through. They folded the case of labels, allowed tolerances looser than the stated precision, ignored extra keys, accepted "12.3" for 12.3, tolerated text around the JSON, compared lists as sets, never recomputed derived fields, read a second answer channel, or kept the last of two duplicate keys. Decide each strictness choice once, state it in the answer contract word for word ("one JSON object and nothing else", "labels exactly as listed", "at least four significant figures"), and implement exactly that. reference/patterns/strict-grading.md gives the rules. reference/helpers/grade_kit.py implements them (stdlib only; ship it as the private grader file grade_kit.py). Run `run_probe_battery` after every build that changes the grader (reference/patterns/probe-battery.md). `embed_file` copies a workspace file (grade_kit.py, a tested grade.py) into a marked assignment in program.py, so the program carries its exact text.
