# c35 construction repair: disjoint private alias families

This checklist applies only to proposal
`bbeac26a2dfb5b328a30a0e274f35764d5f4b3c1362f4434db443e602b8498df`
(`c35.persistence_migration`, slot 6). It supplements
`docs/build_acceptance_001.md` and binds the static construction audit
`docs/audits/c21_c35_construction_002.md`, SHA-256
`406eb1bbeb924fff4c414210f5ce4bfe1cf6c6e21e8e2a8876c526bfad846b22`.
The accepted-record SHA-256 is
`e6e167484400d0509d1fea62de879010354ce4cb27fb1c6a3e64472debee3449`.

The existing construction may be reused as repair input after its current run
reaches a terminal, receipted state. This checklist does not authorize a
parallel duplicate build. It does not change the public solver workflow,
ShellSim environment, five product defects, G1-G9 behavioral groups, binary
all-groups pass boundary, workload, or difficulty.

The following checks are blocking. Each must appear exactly once as `passed`
in the hash-bound `build-acceptance.json` described by the common checklist,
with the named private artifacts and measured results.

- `c35-private-catalog-disjointness`: create an evaluator-private catalog
  variant with at least one new canonical perk family containing at least
  three aliases. None of its canonical ID, aliases, fixture identifiers, or
  lookup keys may occur in the public catalog, public fixtures, tickets,
  simulator documentation, visible repository, image, or model prompt. Record
  the exact public/private set comparison and a zero-intersection result. The
  private catalog remains evaluator-only.
- `c35-private-alias-merge`: include hidden handcrafted and seeded-random cases
  in which all three new aliases refer to the same canonical perk while their
  inputs disagree on `owned`, `xp`, and source/order facts. The expected result
  must apply the admitted merge rules exactly: `owned` is OR, `xp` is max,
  sources are a sorted union, and the first-minted UUID is retained. Record the
  input facts, independent expected output, and actual reference output for
  every case. The old hidden artifact that maps public aliases into three
  separate canonical perks does not satisfy this check.
- `c35-random-family-coverage`: change the seeded generator so a documented,
  nonzero stratum uses evaluator-private aliases from the new family. Hidden
  player IDs or unknown names alone do not establish alias-family coverage.
  Retain Unicode, unknown-name quarantine, checksum, idempotence, crash,
  retention, and other existing random strata. Record deterministic case
  counts and the generated family-membership summary across three identical
  runs.
- `c35-public-alias-mutant`: add a targeted mutant that correctly implements
  every public alias family and all unrelated migration behavior but does not
  generalize to the evaluator-private family. It must pass the visible alias
  fixtures and fail the private alias criterion for the intended reason. A
  mutant that also fails hidden player IDs, unknown-name handling, checksums,
  or other random cases does not isolate this claim.
- `c35-alias-leakage`: scan the complete solver-visible repository, ShellSim
  image, task text, command documentation, transcripts, and published source
  manifest for the private canonical ID, every private alias, private fixture
  marker, and generator seed/marker. Record zero hits and bind both the scanned
  surface manifest and private-term manifest by hash. Do not publish the terms
  in a solver-visible artifact.
- `c35-repaired-control-matrix`: run the reference, original buggy script, five
  single-defect mutants, hardcoding mutant, naive-gate mutant, reject-all
  control, and new public-alias-only mutant through the repaired final embedded
  grader. The reference must pass every G1-G9 group identically three times;
  each negative must fail its intended group, and the single-defect matrix must
  retain its admitted diagonal discrimination. Bind the final catalog,
  generator, fixtures, harness, grader, TaskSpec, rendering, and runtime image
  hashes.
- `c35-terminal-receipt-and-runtime`: obtain a complete final-session receipt
  after the repair and run the controller-owned oracle, independent solver,
  baseline, and adversarial trials through the actual final task package.
  Builder reports and earlier network-blocked replay are supporting evidence,
  not substitutes. Preserve the admitted ShellSim edit/run loop and record
  measured solver usability and time.

If construction instead keeps the visible catalog exhaustive, or cannot build
a private disjoint alias family without changing the public contract, it must
return for a hash-changing clarification and fresh review. It may not weaken
the accepted anti-shortcut claim inside construction.
