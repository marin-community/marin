# c30 verifier-design status

The authoritative construction input is the original admitted c30 slot-5 proposal,
SHA-256
`e7a143b517fe913295831e736a2fcd99cd7874b9d47234a7b5bf1d1cae3b50df`.
It preserves the intended task: audit 15 defects in a synthetic performance memo,
recompute the supplied figures, remove causal overclaims, expose incompatible
definitions and attribution windows, and keep recommendations inside the supplied
action menu. Its private reward contract includes an executable format/quote
precheck, an anchored weighted `0/1/2` semantic rubric, four must-pass conditions,
disqualifiers, and capped false-positive penalties.

That contract does not fit the unextended TaskCompendium dc6 native-judge surface.
The native surface offers a reference score or an equal-weight binary checklist
mean, and the pinned Harbor lowering rejects multistep `all_required_steps`.
Using `mean` would dilute a failed deterministic or critical gate; using `final`
would discard the precheck result. The authorized implementation path is therefore
a reproducible composite-verification extension that executes the machine checks
and semantic judge and preserves the original aggregation semantics. Construction
must remain pending until the exact extension, lowering, and end-to-end runtime
evidence satisfy the proposal-hash-specific build checklist. Schema validity or two
independently runnable verifiers is not evidence that their rewards compose.

The current extension contract can represent the admitted score only with an
explicit mapping. Each `0/1/2` anchor becomes calibrated partial-credit and
full-credit native binary criteria with the original weights. The four critical
conditions and global disqualifiers force overall reward zero. A machine penalty
implements `-1` per false positive capped at `-4`; a separate conditional cap,
triggered at four false positives, zeros exactly the register-section judge
indices while retaining other earned credit. The exact-hash checklist is
[`build_acceptance/e7a143b517fe913295831e736a2fcd99cd7874b9d47234a7b5bf1d1cae3b50df.md`](build_acceptance/e7a143b517fe913295831e736a2fcd99cd7874b9d47234a7b5bf1d1cae3b50df.md).

## Native-only investigations

Two native-only redesigns are retained as immutable evidence. They are not the
selected construction contract and no task build or calibration was launched from
either one.

Redesign 001, proposal
`6f9d15b8a72dc6fd53ab731990457edcc087a4ef5e27eadc2c262a63f56ab2f6`,
replaced the original reward with 39 equal-weight binary criteria. A deterministic
audit showed that severe causal, window, and action errors still received rewards
from `0.8462` to `0.9744`. The proposal is revoked in
`data/revocations.json`; the audit is
[`audits/c30_redesign_001.md`](audits/c30_redesign_001.md). The revocation remains
in force and permits reuse only as admission-repair context.

Redesign 003, proposal
`f6252a6c692070b8cc2760bc21053e85b58d2a938ddeb402caf582fc479109d7`,
conjoined four severe-error predicates into each of 40 native binary criteria. A
fresh review accepted that representation, but the run completed before the
composite-verifier direction was authorized. It is now an optional research result,
not a replacement for the original proposal. Its accepted artifact is
`runs/c30-supported-redesign-admission-003/raw-pull/accepted.json`, SHA-256
`17932a7da7c03727062fef6bccac63f81bc6de3776f01086ab1beca61d48b54d`.
The accepting review also identified an uncorrected narrative arithmetic error:
Table 2 spend is `12,000` before and `14,500` after, or `+20.8%`, rather than the
proposal's `16,500` and `+37.5%`. No build used this artifact.
