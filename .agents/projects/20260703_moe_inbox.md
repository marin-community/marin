# Revised Goal
Build the Hopper MGPU MoE MLP as a staged source-push MLP with an MLP-level custom VJP.

Do not make permute_up, W2, return, and combine separately differentiated public units. Treat the whole expert MLP as the differentiable boundary:

x, route_assignments, route_weights, w13, w2
  -> source_push_moe_mlp(...)
  -> y
The intentional checkpoint boundary is:
H_expert_major = W13 preactivation
where H = [gate, up], before silu(gate) * up.

## Forward
Production forward should be staged but structured around H:

1. Build SourcePushPlan
   - compact routing metadata
   - route -> destination rank/local expert/row
   - inverse metadata for returning/combine
   - per-expert capacity/counts
   - route_weights aligned with expert-major rows

2. source_push_w13_h
   source-owned x routes are pushed to destination expert ranks
   W13 runs with WGMMA
   output:
     H_expert_major: [local_experts, capacity, 2 * intermediate_dim]

3. source_push_w2_return_combine
   read H_expert_major
   compute A = silu(gate) * up on load/prologue
   compute A_weighted = route_weight * A
   run W2 with WGMMA
   return partial y routes to owning source rank
   combine top-k contributions into y: [tokens_per_rank, hidden_dim]

**Key point**: forward should ideally not materialize post-SwiGLU A as the stable boundary. H is more valuable for backward. If needed for incremental integration, a temporary A materialization path is acceptable, but it should not become the design target.

### Residual Policy
Save for backward:
H_expert_major
SourcePushPlan / inverse route metadata
route_weights in expert-major order or enough metadata to recover them
needed static config / dimensions
Do not save:
recv_x / packed x
post-SwiGLU A
per-route W2 output Y
temporary inbox/scratch buffers
This makes backward pay rematerialization for x routing, but avoids recomputing W13 just to get SwiGLU derivatives.

## Backward
The custom VJP should be written at the MLP level:
`dy -> dx, dw13, dw2, d_route_weights`

### Backward sequence:
1. Route dy to expert-major rows
   dy_expert_major uses the same SourcePushPlan inverse mapping.

2. Recompute activation from saved H
   gate, up = split(H)
   A = silu(gate) * up
   A_weighted = route_weight * A

3. W2 backward
   dA_weighted = dy_expert_major @ W2.T
   dW2 = A_weighted.T @ dy_expert_major

4. Router-weight gradient
   d_route_weight = dot(dA_weighted, A)
Then:
5. SwiGLU backward
   dA = route_weight * dA_weighted
   dH = d_swiglu(dA, H)

6. Rematerialize expert-major x
   rerun the source-push/repack path for x using SourcePushPlan.

7. W13 backward
   dW13 = x_expert_major.T @ dH
   dx_expert_major = dH @ W13.T

8. Return/combine dx
   route dx_expert_major back to source-owned tokens
   sum top-k contributions into dx

The router assignment itself remains non-differentiable. The differentiable router output is the route weight / score path.
### Why H Is The Right Checkpoint

Saving A helps dW2, but not dSwiGLU; backward would still need gate/up preactivations and would likely recompute W13. Saving packed x helps dW13, but it is large and does not help activation backward. Saving H lets us do dW2, d_route_weight, and dH without recomputing W13.

Natural Workstreams
In the main thread, this splits cleanly into sub-agent-sized chunks:
API/config/plan contract: define SourcePushPlan fields needed for both forward and backward; remove kernel-local assumptions.

Forward H boundary: make W13 produce H_expert_major; make W2 consume H and apply SwiGLU + route weight internally.

Custom VJP skeleton: wrap the staged forward as one jax.custom_vjp; wire residuals and reference backward first.

Backward kernels: implement dy routing, dA/dH/dS, dW2, dW13, and dx return/combine.

Benchmark/integration: H100 target runs, decomposition rows, correctness logs, comparison to current PR and issue #6597 goals.

The core spec change is: Phase 5 is no longer “make permute_up faster” in isolation. It is “make a source-push MoE MLP whose saved forward state is H_expert_major, with forward and backward both organized around that boundary.”

**Workstream Dispatch**

Use subagents for independent workstreams. The top-level agent owns the contract, reviews integration points, and keeps the logbook/current issue updated. Subagents should work against the shared MLP-level design, not invent separate kernel APIs.

Coordinator responsibilities:

```text
- owns final SourcePushPlan / custom VJP contract
- assigns workstreams
- keeps .agents/logbooks/6597-moe-mgpu-forward.md updated
- coordinates in #6597-forward
- prevents divergence from the H_expert_major checkpoint design
- integrates subagent patches
- launches/babysits or delegates H100 benchmark runs
```

Subagent heartbeat:

```text
- dev subagents: poll every 5-10 min
- H100 babysitting subagents: poll roughly hourly unless run is short/fragile
- each subagent reports: current hypothesis, files touched, blockers, benchmark/test status
```
