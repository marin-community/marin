# MoK EP64: Task Logbook

## Current TL;DR

The upstream kernel explicitly supports EP64, while Marin's adapter is fixed to process-local EP4.
The first treatment uses 64 supervised one-GPU JAX processes and PyTorch symmetric memory only as
the remote workspace mapper. A standalone JAX+Torch probe must pass before the fused kernel changes.
Native CUDA fabric VMM is the fallback if the PyTorch backend cannot expose all 64 peers.

## Scope

- Goal: Run MoK forward/backward training across one 64-GB200 NVLink domain.
- Primary metrics: numerical parity, exact drop accounting, bounded failure closure, stable 25/100
  step training, tokens/s, MFU, HBM, and host-memory headroom.
- Constraints: one hard NVLink domain, no task retries, runtime-staged inputs first, no claim of
  strict droplessness below factor 64.
- Coordinating issue: https://github.com/marin-community/marin/issues/8108

## Baseline

- Stable local EP4 snapshot: `bceba3c7814f45f556109f202386f85c12844527`.
- Sealed v15 scale: one-rack 25-step 309,026.654 TPS and two-rack 100-step 553,963.070 TPS, both
  data-parallel compositions of EP4 rather than EP64.
- Existing EP64 fixed-all-to-all hero: about 309k TPS at the production rack shape; a fresh matched
  control is required for final comparison.

## Hypothesis Queue

### Active

- `MOK-EP64-H1`: PyTorch 2.11 symmetric memory exposes all ranks in one NVL72 while coexisting with
  one-GPU JAX processes. Next: EP8 then EP64 standalone probe.
- `MOK-EP64-H2`: Upstream's EP64 BF16 instantiation works with Marin's staged workspace and JAX
  schedule. Next: small forward/VJP parity after H1.
- `MOK-EP64-H3`: Full-expert cancellation and status agreement close synchronous failures without
  a hang. Next: rank-0/rank-63 matrix after H2.

### Blocked

- `MOK-EP64-H4`: Cross-process XLA zero-copy. Blocked on a correct symmetric staged implementation.

### Falsified / Dead End

- JAX/NCCL direct one-sided EP64 transport on the current stack: rank-32 metadata-only failures are
  recorded in https://echo.oa.dev/wiki/94 and the MoonEP logbook.
