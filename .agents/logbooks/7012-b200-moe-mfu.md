# B200 MoE MFU: Task Logbook

Experiment ID prefix: `B200MFU-###`. All runs on a shared 8×B200-per-node cluster
(single node unless noted); "same-node pair" means both arms pinned to one node,
run sequentially. Driver: `grug_moe_row13.py` on branch
[`mcwitt/sonic-cute-wgrad`](https://github.com/marin-community/marin/tree/mcwitt/sonic-cute-wgrad)
(off `sonic-cute-moe-b200`). Row-13 config (#6979): d2560 / 26L / 64 experts top-4 /
MHA / EP1+FSDP / MuonH / stacked-scan / b128 / seq4k / `gpu_fa4_cute` attention.
Steady-state median MFU vs B200 bf16 peak (2.25e15 FLOP/s/GPU), 20 steps, warmup 8.

## Scope
- Goal: raise single-node B200 MFU toward the ≥20 %-on-a-rack target of #7012; identify which levers actually move step time.
- Primary metric: `steady_median_mfu_b200` from the row-13 driver (tokens/s as secondary).
- Constraints: shared cluster etiquette (≤2 nodes at a time); no cluster identifiers in durable output.
- Coordinating issue: https://github.com/marin-community/marin/issues/7012

## Current TL;DR
Single-node step time is **not GEMM-bound**. Profile (B200MFU-007): attention 30.3 %,
remat recompute ~25 %, MoE GEMMs 24 %, optimizer 4.4 %, NCCL ~10 %. Kernel-side wins
(wgrad shim, tile autotune) are real in microbenchmarks but ≤0.1 pp e2e. Largest
open lever: attention-only remat (est. +2–3 pp). NVIDIA-stack probes (ragged-dot
fusion, LHS) are null on upstream jax 0.10.1 — the cuDNN ragged-dot fusion fires but
has no autotuner configs on SM100 (B200MFU-009); NGC 26.05 container test in flight.

## Current baseline
d2560: **15.01 %** MFU (sonic_cute + quack wgrad + 256×256 tiles, B200MFU-005).
d5120: **17.88 %** (same stack, B200MFU-006). Controls match #7012 table (14.9 / 17.8).

## Hypothesis Queue

### Active
- `H-remat`: attention-only remat (split per-block checkpoint; MoE outside) reclaims most of the ~25 % recompute tax → +2–3 pp. Evidence: B200MFU-007/-008. Next: implement block-split checkpoint in `experiments/grug/moe/model.py`.
- `H-ngc`: NGC JAX 26.05 (NVIDIA XLA + cuDNN) makes native `ragged_dot` competitive with QuACK. Evidence: B200MFU-009 (fusion exists upstream but unconfigured). Next: run B200MFU-010 microbench + e2e arms in container.
- `H-pgle`: PGLE closes part of the ~9 % idle share. Next: two-phase capture wiring.
- `H-mxfp8`: MXFP8 on QuACK seam; ceiling ~1.1× e2e for MoE-only (24 % share) — larger if attention/dense included.
- `H-attnbwd`: FA4 bwd at 13.8 ms vs fwd 5.9 ms (~2.3× FLOPs → roughly fair); check kernel efficiency headroom before acting.

### Blocked
- `H-te-ep`: TransformerEngine MoE + NCCL_EP for rack-scale EP. Blocker: single-node phase. Resume when: multi-node scaling starts. (NGC 26.05 ships TE 2.15.)

### Falsified / Dead End
- `H-wgrad`: QuACK varlen-k wgrad ≫ XLA wgrad e2e. Falsified: +0.06–0.08 pp only (B200MFU-003/-004). Kernel is bit-exact and kept (completeness + MXFP8 substrate).
- `H-tiles`: per-site tile autotune lifts e2e. Falsified: ×1.08–1.28 microbench, ≤+0.04 pp e2e (B200MFU-005/-006).
- `H-comms`: EP1+FSDP collectives dominate. Falsified: NCCL ~10 % of step (B200MFU-007).
- `H-ns`: batching MuonH Newton-Schulz is a big win. Falsified: NS total = 0.60 pp (B200MFU-008a); already batched via `_newtonschulz_4d_distributed`.
- `H-savemoe`: `remat_mode=save_moe` skips MoE recompute. Falsified for sonic_cute: +65 GiB, 0 gain — `_expert_mlp` is a custom_vjp whose residuals can't be name-saved through `jax.checkpoint` (B200MFU-008b).
- `H-flags`: ragged-dot-fusion / LHS flags help on stock jax. Falsified e2e and explained: sonic backend never emits `ragged_dot` HLO; when forced, fusion fires then autotuning fails "No supported configs" (B200MFU-009). LHS likely already default.

## Entry Log

### 2026-07-13 — B200MFU-001: controlled baseline repro (scatter→sonic path)
- Command: `sbatch grug_row13_repro.sbatch` (8×B200, 1 node; driver defaults, `MOE=sonic`).
- Result: **12.499 %** MFU — matches the 12.5 % in the #7012 table to 3 digits, from an independent checkout + venv (cudnn 9.19.0.56, nccl 2.28.9 pins required; quack-kernels install silently downgrades cudnn — re-pin after).
- Interpretation: stack fully reproduces the published baseline; safe to iterate.

### 2026-07-13 — B200MFU-002: wgrad varlen-k shim parity (1×B200)
- Commit: `595808412` (`quack_grouped_wgrad_gemm`: dw[e]=actsᵉᵀ·gradsᵉ via `cu_seqlens_k`; zero-copy transposed views, A m-major / B n-major, expert = trailing L mode; `SONIC_CUTE_WGRAD=xla` fallback).
- Result: bit-exact vs XLA `ragged_dot` vjp (even / heavily-ragged / empty-expert groupings; empty experts exactly 0). E2e grads identical under either backend (rel ~1 % vs scatter, same as fwd-only QuACK).
- Interpretation: correctness fully established; kernel usable for perf measurement.

### 2026-07-13 — B200MFU-003/-004: wgrad MFU, same-node pairs
- Command: `SONIC_CUTE_WGRAD=xla sbatch …` vs default, pinned to one node; repeated at d5120.
- Result: d2560 14.89→14.97 (+0.08 pp); d5120 17.82→17.88 (+0.06 pp). Controls match #7012 (14.9/17.8). `replicated` (two pairings, consistent direction).
- Interpretation: wgrad was not a bottleneck; "complete MoE-on-QuACK" ≈ +0.5 % tokens/s.

### 2026-07-13 — B200MFU-005/-006: QuACK tile/cluster autotune
- Command: 96-config 1-GPU sweep (`tune_quack_gemms.py`): tiles {128,256}² × cluster {(1,1,1),(2,1,1)}, all 6 call sites, d2560+d5120 shapes (TK=262144, E=64).
- Result: (256,256)+(2,1,1) wins **all 12 site×width combos**, ×1.08–1.28 (gated fwd d5120 1186→1472 TF/s ≈ 53→65 % peak). E2E (same nodes as -003/-004): d2560 15.01 (+0.04 pp), d5120 17.88 (±0).
- Interpretation: step not GEMM-bound; adopted tiles anyway (commit `dbcf65b2e`).

### 2026-07-14 — B200MFU-007: step-time anatomy (profiled)
- Command: driver `PROFILE_DIR` knob (commit `e807bd831`), 8×B200 d2560; attribution run with `XLA_FLAGS="--xla_gpu_enable_command_buffer=''"` (command buffers strip kernel→op names on GPU).
- Result (share of GPU kernel time): attention 30.3 % (fwd 6.7, bwd 23.6 incl. remat'd fwd) · backward-other 27.6 % (mostly `checkpoint/rematted_computation`) · MoE 24.0 % · optimizer 4.4 % · NCCL ~10 %. Peak mem 54/192 GiB ⇒ `recompute_all` remat buys nothing we need.
- Interpretation: remat tax (~a full fwd re-run, ~25 %) is the largest addressable item; MXFP8 ceiling quantified at ≲1.1× e2e for MoE-only.

### 2026-07-14 — B200MFU-008: optimizer + remat ablations
- (a) `SCALE_MUON_NO_NS=1`: 15.61 % vs 15.01 % ⇒ NS = 0.60 pp total; already expert-batched (`_newtonschulz_4d_distributed`). Not a lever.
- (b) `REMAT_MODE=save_moe`: 14.96 %, mem 54→119 GiB ⇒ null: saves dispatch tensors but `_expert_mlp` custom_vjp residuals (gu/h) force GEMM re-run in bwd regardless of save-policy names.
- Next action: attention-only remat via block-split checkpoint (H-remat).

### 2026-07-14 — B200MFU-009: NVIDIA flag probes on stock jax 0.10.1
- E2E: `xla_gpu_experimental_use_ragged_dot_fusion` null on sonic arm (12.52→12.52; sonic never emits `ragged_dot` HLO — needs jax-triton, not `lax.ragged_dot`). `xla_gpu_enable_latency_hiding_scheduler` null (15.01→14.97).
- Microbench (`ragged_fusion_probe.py`, 1×B200, TK=262144 × d2560 × F1280, E=64): flag OFF, `lax.ragged_dot` lowers to a **dense-materialized** [262144, 163840] cuBLAS matmul — 22.6 TF/s effective (~65× worse than QuACK). Flag ON: `ragged_dot_fusion` (kind=kCustom, `__cudnn$fusion`) fires, then **autotuning fails: "No supported configs found"** on SM100 + cuDNN 9.19.
- Interpretation: the fused implementation exists upstream but is unusable there; consistent with "made performant in NGC 26.05". → H-ngc.
