# Snowball RL handoff for Megatron and Levanter

## Target

Run Snowball RL with SkyRL orchestrating, Megatron training, and native Levanter serving rollouts. Start on the H100 quick-loop topology and keep the existing Megatron + compiled vLLM recipe as the control. The first milestone is a run that trains on Levanter rollouts, publishes updated Megatron weights back to Levanter, and resumes from a Megatron checkpoint. Qualify that path on matched training goodput, policy agreement, and held-out quality before changing the default.

## Starting point

Use `experiments/post_training/snowball_rl.py` on Marin main. The P40 quick loop allocates 32 H100s to the Megatron policy and eight H100s to a disaggregated vLLM engine. The checked-in `speed-medium` and `learning-medium` use asynchronous generation with up to two steps of staleness and truncated importance sampling. Use the same allocation and resolved learner geometry for the candidate. Render both plans and record the source SHA, initializer and tokenizer revisions, immutable run versions, topology, and resolved settings. Add a checkpoint-enabled synchronous smoke variant of this layout first. Use the asynchronous recipes as written for the subsequent comparison. ## Implementation

### 1. Add an opt-in SkyRL rollout backend

Wire Levanter into SkyRL's inference-engine interface and current role plan. Start the native server as an Iris-managed inference role. Keep the trajectory runner, grader, token masks, reward and reference-policy configuration, and Megatron checkpoint lineage in SkyRL. Exercise the same entry points the chosen recipe uses, including startup readiness, pause, resume, timeout, cancellation, bounded admission and shutdown. [SkyRL engine interface](https://github.com/marin-community/marin/blob/142a4206575fc8b9be72d5b6cda833c2529165b8/vendor/skyrl/skyrl-train/skyrl_train/inference_engines/base.py)

- Send authoritative prompt token IDs to `POST /v1/levanter/generate`. The binary endpoint uses a versioned JSON header and safetensors. Map sampled token IDs, per-token logprobs, completion limits, finish/stop state and policy identity back to SkyRL. The demonstrated binary frame returns one score mode per server and its choices need explicit finish-reason metadata for SkyRL’s `stop_reasons` field. Fail startup for unsupported recipe options and exercise multi-choice, truncation, masking and exact-token continuation with a tool response. [Binary endpoint #12044](https://github.com/marin-community/marin/pull/12044) · [SkyRL chat continuation](https://github.com/marin-community/marin/blob/142a4206575fc8b9be72d5b6cda833c2529165b8/vendor/skyrl/skyrl-train/skyrl_train/inference_engines/chat_continuation.py)

- Trace what `rollout_logprobs` means for the chosen preset and its importance-sampling denominator. Levanter can return raw policy logprobs or behavior logprobs after sampling transforms. Run a temperature/top-p fixture where those differ, verify masks and non-finite handling, and extend the versioned frame if a recipe needs both. Keep the RL objective's KL penalty and reference behavior as configured. Qualify strict numerical zero-KL separately if the recipe needs it. The existing bitwise zero-KL result is for sampled scores in a bounded TPUv4 Levanter-learner test. [Score modes #12062](https://github.com/marin-community/marin/pull/12062) · [Strict parity #12073](https://github.com/marin-community/marin/pull/12073)

- Where the recipe enables router replay (R3), use the existing Megatron replay input. Convert the native expert trace from full-sequence positions to response predictor positions. For zero-based response token `j` and prompt length `p`, use row `p + j - 1`. The first response token uses row `p - 1`. Match MoE layer order, expert numbering, top-k order, mask and sentinel conventions before passing data to the existing packer. Test the first and last response positions, mixed lengths and continuation across a tool response. The medium presets alone do not qualify the long-context agentic recipe. [Native route capture #12051](https://github.com/marin-community/marin/pull/12051) · [Megatron replay consumer](https://github.com/marin-community/marin/blob/142a4206575fc8b9be72d5b6cda833c2529165b8/vendor/skyrl/skyrl-train/skyrl_train/workers/megatron/megatron_model_wrapper.py)

### 2. Publish Megatron policy weights

Keep the existing Megatron expert-block sender and SkyRL synchronization lifecycle. Implement a Levanter receiver against the sender's versioned inventory and transfer plan. Use the existing H100 transport where it fits. Host staging is acceptable for the first implementation if it fits the memory budget and the refresh pause is measured. Validate names, shapes, dtypes, dense and expert coverage, and transfer integrity. Separately verify the effective weights after Levanter repacks, casts and reshards them. Check expert identities, gate/up layout and tied weights with a small deterministic fixture, then compare model outputs on the real checkpoint. A verified Megatron export through the usual model loader can bootstrap the first sample and test the layout. Exercise the live receiver before claiming closed-loop success. [Expert-block driver](https://github.com/marin-community/marin/blob/142a4206575fc8b9be72d5b6cda833c2529165b8/vendor/skyrl/skyrl-train/skyrl_train/weight_sync/expert_block/driver.py) · [Single-server install #12090](https://github.com/marin-community/marin/pull/12090)

Use SkyRL's pause → publish → resume sequence. Stage and validate the candidate before visibility. Match SkyRL’s pause contract. Abort running and queued requests, preserving generated tokens and their original policy stamps for running requests. Return zero completion tokens for requests that were still waiting. Each server must install the full snapshot and invalidate old model-dependent KV, prefix and routing state before acknowledging it. Resume only after every eligible server confirms the same verified snapshot. Record a receipt mapping the immutable Levanter `policy_id` to SkyRL's policy step. Keep the server-local `model_version` as diagnostic metadata. The disaggregated trainer opens the next leases with `resume_generation(policy_step=global_step + 1)`. Match that convention in the adapter and retain the Megatron checkpoint step in the receipt. Send `expected_policy_id` on each rollout request, handle HTTP 409 as a version mismatch, and preserve the existing per-token policy stamps and staleness checks on admission. Async rollouts selected within the configured age limit are valid when their scores and stamps identify the policy that actually produced them. [SkyRL trainer](https://github.com/marin-community/marin/blob/142a4206575fc8b9be72d5b6cda833c2529165b8/vendor/skyrl/skyrl-train/skyrl_train/trainer.py) · [Policy identity #12056](https://github.com/marin-community/marin/pull/12056)

On timeout or a partial install, keep admission paused until the eligible fleet converges on one verified snapshot, or end the attempt. Make retries of an identical snapshot idempotent, and reject conflicting contents for the same ID. Test out-of-order and duplicate publication, interrupted transfer, a replica failing after another has installed, and retry after a trainer or server restart. After checkpoint recovery, republish the recovered model before taking traffic. Roll back at a controlled restart using the vLLM preset and a retained Megatron checkpoint.

## Run order and exit criteria

| Stage | Evidence required to move on |
|---|---|
| CPU contract tests | Both plans render. Exact tokens, scores, stops, masks and version stamps survive the adapter. Two simulated serving replicas cover failed and partial publication, stale request rejection, and clean retry. |
| Frozen H100 parity | Score the same prompt and continuation IDs at the initializer and after a changed publish. Compare native inference, the aligned Megatron policy forward, and compiled vLLM at each snapshot. Report score error tails, signed log ratios, k3 KL, clipped fraction and effective sample size. Verify route coverage and alignment wherever R3 is active. Use the matched control to set numerical tolerances. |
| Closed-loop H100 smoke | Publish the initializer and train update one. Publish the changed policy and record its receipt. Save a Megatron checkpoint after update one and restart before admitting update two’s batch. Verify the restart republishes the checkpoint’s post-update weights, then require update two to consume tokens stamped with the recovered snapshot’s verified policy ID. Report finite loss and gradient norm. Exercise a stale request and a publish failure. Keep the checkpoint and receipts. |
| Matched speed and learning | Run `speed-medium` for 10 updates (measure 2–10) and `learning-medium` for 25 updates (held-out EvalLite at 0 and 25). Match tasks, seeds, initializer, tokenizer, sampling, limits, reward, learner geometry, staleness, checkpoint and evaluation settings within each pair. Record the existing speed, staleness-zero policy agreement and held-out quality gate results. For the speed guard, use `policy/mismatch/staleness0/kl_k3` from the existing preset. |
| Evidence for a default switch | Demonstrate steady state under repeated weight refresh and at least one real multi-replica failure/recovery test. For an agentic cutover, also qualify its actual multi-turn context, tool parsing and R3 settings. Require no mixed-snapshot admissions, no rollouts above the configured age limit, no corrupt samples, passing quality/agreement gates, and at least matched learner goodput. Rehearse the vLLM rollback. |

For frozen parity, feed the supplied IDs through Levanter’s native prefill and decode path and gather the target token at each causal predictor row. The `_public_serving_oracle` helper in `test_snowball_engine_replay.py` shows how to obtain those logits. Use the Megatron policy’s training logprob forward and vLLM’s prompt logprobs over the concatenated IDs, retaining only the continuation positions. Check raw model scores first, then verify behavior scores separately under the agreed sampling transforms.

Use **response tokens accepted by Megatron per allocated H100-hour** as the primary throughput metric, and report accepted tokens per second and elapsed training time excluding eval alongside it. Count generated, graded, accepted, stale, failed, cancelled and shutdown-discarded tokens. Report p50/p95 policy-refresh pause, queue wait, p90 TTFT, request errors, cache use, and host and accelerator memory. Attribute losses to transfer, repack, drain, startup or scoring before tuning. For matched AgentX service checks, use concurrency 128 and a 180-second measurement. Aim for p90 TTFT within 20% of vLLM and prioritize throughput. A separate TPU follow-up can use v5p or v6e with the one-hour probe cap. Keep checkpoint and model access region-local and retained artifacts under 1 TB. [Timing and run metadata](https://github.com/marin-community/marin/blob/142a4206575fc8b9be72d5b6cda833c2529165b8/docs/recipes/rl-experiments.md) · [Example of generated vs. consumed tokens](https://github.com/marin-community/marin/issues/8936#issuecomment-5559559725)

For each comparison, retain the resolved configs, Git SHA, Iris job and attempt IDs, policy receipts, control reports, and checkpoint references. Stage the PRs around the backend and wire contract, the receiver and publication lifecycle, then the opt-in recipe and comparison evidence. Use the current inference stack for prerequisites that are already under review. Deliver the opt-in H100 path and qualification evidence. Leave the default switch and TPU qualification to follow-up decisions.
