## Source-backed findings

The README gives direct examples for FASTA search, cascaded clustering and taxonomy assignment, and states memory expectations qualitatively in residues. It explicitly distinguishes estimated identity for `search` from its `easy-search` default. Workflow shell sources clarify data transformations and output artifacts, which is why these steps are represented as task-sized units rather than every lower-level utility.

The mutable Wiki tutorial gives a much richer scientific case: CSF metagenomic reads are translated and searched against taxonomically annotated Swiss-Prot; tutorial steps produce per-read taxonomic results, filter candidate pathogen reads, assemble proteins with Plass, cluster representative sequences and annotate them. It describes 14 million original reads and 226,908 reads in the post-human-filtering set, links a `mystery_reads.fasta`, and names a Swiss-Prot `2018_03` FASTA plus mapping TSV. The tutorial cites Piantadosi et al. 2018 and frames Powassan virus as the intended diagnostic mystery. The record preserves the missing exact SRA accession and the fact that source inspection does not validate the clinical conclusion.

`parseproteomealignments.cpp` shows one count for a query-sequence/target-source pair when that query sequence has any alignments to the target source, normalized by query-source entry count. Its dense matrix is allocated using query-source count times target-source count; this is a concrete resource limitation for large proteome collections.

## Data reconciliation and boundaries

The two example FASTA files are kept separate because shared sequence identity/provenance was not inspected; the README uses them as a query/target pair. Swiss-Prot candidates are separate records where the general README's named downloadable database and the tutorial's exact `2018_03` snapshot have different version specificity. The tutorial reference pairs its 2018_03 FASTA and mapping TSV as assets of one curated database product. NCBI taxonomy dump and UniProt current ID mapping remain separate assets within a taxonomy-reference record because the setup workflow joins them to annotate target sequence keys; neither is itself study data. No biological asset was downloaded or previewed.
