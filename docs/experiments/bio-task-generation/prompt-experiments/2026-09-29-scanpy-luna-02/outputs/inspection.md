GitHub `main` was the available repository reference, but an immutable repository SHA could not be resolved because the GitHub API endpoint was inaccessible in the browser tool. Documentation URLs using `stable` and `latest` are moving aliases; the stable Pearson-residual tutorial's rendered environment reports Scanpy `1.10.0rc2.dev6+g14555ba4`. Treat this as a revision gap, not a claim that the full current repository was pinned.

## Repository and scientific uses

Scanpy is a Python toolkit for single-cell expression analysis. Its documented use spans count-matrix preprocessing and QC, feature selection, dimensionality reduction, graph construction and clustering, embeddings and visualization, marker-gene analysis, integration and trajectory inference. API source listings group preprocessing (`pp`) separately from tools (`tl`): preprocessing changes matrices, while tools add interpretable annotations. Tutorial examples support complete analysis compositions, which are the strongest task candidates in this pass.

The inventory records three source units: `scanpy_legacy_pbmc3k_preprocess_cluster_annotate`, `scanpy_pearson_residuals_pbmc3k_pbmc10k`, and `scanpy_current_basic_clustering`. Their overlap reflects distinct scientific uses and tutorial contexts: a classic PBMC workflow, Pearson-residual feature selection and downstream analysis across two chemistries, and a contemporary batch-aware workflow with QC reassessment. The first two share the PBMC3k observations and are linked. The marker list is a separate annotation-reference record, not additional study observations.

## Data records and relationships

`10x_pbmc3k_v1_filtered` describes the filtered 10x PBMC3k matrix. The legacy tutorial uses a similarly named archive; the Pearson-residual tutorial gives the versioned 1.1.0 asset URL and SHA256. The available evidence supports treating these as the same observations and source asset, while the legacy workflow's output is a derived representation. `10x_pbmc10k_v3_filtered` is a separate product and observations, not merged with PBMC3k. Both archives have documented checksums, but checksums were not independently verified. `scanpy_pbmc_marker_reference` captures the 12-symbol list and cell-type associations used for biological interpretation; it is not a measured dataset or an independent ground-truth annotation.

Direct data access, file previews, execution, exact terms, and redistribution eligibility were not checked. Dataset records preserve the documented URLs and hashes and state unknowns. A valid authoring path is to start from source matrices and require durable AnnData outputs plus scientifically justified QC/HVG/cluster evidence; deterministic grading, objective thresholds and suitability still need separate design and validation.

## Gaps, relationships and stopping point

The classic and Pearson-residual units can be compared as alternative normalization/feature-selection strategies on PBMC3k; the latter adds PBMC10k and an explicit memory tradeoff because residual transformation densifies the matrix. The current batch-aware clustering unit may connect with the API's integration operations, but its dataset identity remains unresolved. A useful next pass should inspect the complete current clustering page/source, the hematopoiesis trajectory workflow and its data, integration examples, differential-expression/marker ranking semantics, doublet detection, and bundled dataset API source.

This pass stopped after one source-map sweep and focused inspection of three tutorial contexts. The API and tutorial indexes revealed additional clearly relevant leads, but the allotted lightweight investigation window did not permit source-level inspection of each. Public web reads were used; direct retrieval failed for the current clustering page (and for the GitHub API SHA endpoint), so those limitations are recorded above.
