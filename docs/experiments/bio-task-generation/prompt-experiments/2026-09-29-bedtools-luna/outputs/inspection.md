## Repository scope and inspected material

The README describes bedtools as genome arithmetic over BED, BAM, GFF/GTF, and VCF, including intersection, merge, count, complement, and shuffle operations, and notes that command combinations support larger analyses. The GitHub root lists `data/`, `docs/`, `genomes/`, `scripts/`, `src/`, `test/`, and `tutorial/`, plus build files and README. This discovery pass inspected the README; tutorial's data setup and sections on intersect, merge, and complement; relevant intersect, coverage, genomecov documentation; the repository data directory listing and several named file pages; the release listing; and the overview/source CLI entrypoint search-result excerpt. It did not enumerate or inspect the complete source, tests, scripts, docs, or every tutorial section.

Three units were accepted: CpG island versus exon overlap/count/threshold analysis; broader multi-track regulatory annotation including DNase-I tissue calls; and merge/complement to derive nonredundant exon spans and genomic complement. These boundaries group command options around distinct scientific results rather than creating a record per option. Shared inputs and operations are linked through stable IDs in `units.jsonl`. The same tutorial bundle is one dataset record because its tracks are co-located and participate in connected tutorial analyses; supporting UCSC annotation tracks remain identified individually inside its assets and are not counted as independent studies.

The tutorial describes a Maurano et al. 2012 analysis of DNase-I hypersensitivity sites in fetal tissues and instructs download of 20 tissue BEDs plus CpG, exon, GWAS, genome-size, and hESC ChromHMM files. It explicitly lists brain, heart, intestine, kidney, lung, muscle, skin, and stomach among represented tissues. It says the latter annotation files came from the UCSC Table Browser. This is sufficient to establish a plausible feature-annotation use, not to establish a causal regulatory interpretation. File formats and tutorial commands are source-backed; exact accession, genome assembly, metadata, sizes, hashes, current availability, and redistribution rights remain unknown. The repository-level `data/` listing shows additional compact interval/reference-looking assets, including hg18-labeled knownGene and chr1 GERP/RefSeq/repeat files; they were not treated as a separate study or linked to tutorial records absent evidence of common provenance.

`coverage` documentation supports interval-level breadth/depth and histogram tasks, and `genomecov` documentation supports genome-wide histogram, per-base and BEDGRAPH outputs, but these were not accepted as task units because I did not find or inspect a repository tutorial workflow tying them to a concrete biological objective and data. The tutorial also contains further commands and linked external articles, plus `answers.md`, source code and tests, that remain leads rather than accepted units. A GitHub page retrieval for answers.md and some source/documentation URLs failed or returned cache/access errors; no answer key or inaccessible source was used as evidence.

## Data and limits

The dataset record distinguishes the observed DNase-I-derived intervals from reference/annotation tracks and the repository's separate bundled example assets. No biological datasets were downloaded and no commands, software, or graders were run. The code is a command-line tool suite; the accepted scientific units use bedtools rather than create its algorithms. The README calls the software MIT-licensed, but that says nothing about rights to redistribute external biological data.

The main useful gap for task authoring is pinned, licensed, assembly-matched task data with a clear scientific objective and deterministic output contract. For intersection tasks, resolve coordinate build, track order, duplicate/multiple matches, fractional-overlap interpretation and labeling. For complement tasks, resolve chromosome bounds and whether gaps/alternate contigs count. For the DNase analysis, define whether the task is simply reproducible interval annotation or asks a biologically stronger inference, and supply appropriate evidence if the latter. Related units can be combined for annotation-plus-exon-mask tasks, but each stage should remain separately gradable if intermediate artifacts matter.

Source-backed facts are limited to inspected descriptions, command examples, file listings, and documentation semantics. Candidate task suitability, runtime, deterministic grading, current link availability, and Harbor compatibility remain hypotheses for later authoring and validation. The pass stopped at the assignment deadline/budget before comprehensive repository-wide enumeration; no source inspection should be represented as successful execution or task validation.
